# Звіт з практичної роботи №3. Концептуальна ER-модель у CASE-засобі

## 1. Межі системи
**Предметна область:** Електронний журнал коледжу.
**Процеси, що підтримуються:**
*   Реєстрація та облік студентів, викладачів, академічних груп.
*   Призначення викладачів на дисципліни (навчальне навантаження).
*   Планування та фіксація занять.
*   Виставлення оцінок та відміток про відвідуваність.
**Запитання, на які система повинна відповідати:**
*   Який поточний середній бал студента з певної дисципліни?
*   Хто з викладачів читає "Бази даних" у групі ІПЗ-31?
*   Які студенти були відсутні на занятті 15 жовтня?

---

## 2. Перевірка моделі сценаріями

| Сценарій | Опис дії | Чи підтримує модель? | Пояснення |
| :--- | :--- | :--- | :--- |
| **Додавання нового об'єкта** | Зарахування нового студента до коледжу. | **Так** | Створюється запис у сутності `СТУДЕНТ` із прив'язкою (FK) до існуючої `АКАДЕМ_ГРУПА`. Завдяки кардинальності 0..N до `ОЦІНКА`, студент може існувати без оцінок. |
| **Оновлення** | Зміна назви дисципліни або посади викладача. | **Так** | Оновлюється один атрибут у відповідній сутності (`ДИСЦИПЛІНА` або `ВИКЛАДАЧ`). Зміни автоматично відобразяться всюди завдяки відсутності дублювання. |
| **Видалення** | Звільнення викладача. | **Так** | Запис видаляється із сутності `ВИКЛАДАЧ`. Проміжна таблиця `ВИКЛАДАЧ_ДИСЦИПЛІНА` дозволяє каскадно видалити його навантаження, не видаляючи саму дисципліну. |
| **Перехідний стан** | Переведення студента в іншу групу. | **Так** | Змінюється значення `ID_Групи` (FK) у сутності `СТУДЕНТ`. Усі його оцінки зберігаються, оскільки вони прив'язані до `ID_Студента`. |

---

## 3. Припущення та відкриті питання
**Ухвалені припущення:**
*   Один студент в один момент часу навчається лише в одній академічній групі (зв'язок 1:N).
*   Одне заняття проводиться для однієї конкретної групи одним викладачем.
*   Оцінка "0" або спеціальний код у полі `Значення` може означати відсутність студента (Н).

**Питання, які потребують уточнення у власника вимог:**
1. Чи потрібно зберігати історію переведення студента між групами (з датами)?
2. Чи можуть два викладачі вести одне заняття одночасно (наприклад, лабораторну роботу)?
3. Чи потрібна підтримка різних типів оцінок (залікові, поточні, екзаменаційні бали) як окремого атрибута?

## 4. Концептуальна ER-модель (із розв'язанням M:N)

*Зв'язок M:N між Викладачем та Дисципліною розв'язано через проміжну сутність `ВИКЛАДАЧ_ДИСЦИПЛІНА` (Навчальне навантаження).*

```mermaid
erDiagram
    АКАДЕМ_ГРУПА ||--|{ СТУДЕНТ : "містить"
    АКАДЕМ_ГРУПА ||--o{ ЗАНЯТТЯ : "відвідує"
    
    ВИКЛАДАЧ ||--o{ ВИКЛАДАЧ_ДИСЦИПЛІНА : "має навантаження"
    ДИСЦИПЛІНА ||--o{ ВИКЛАДАЧ_ДИСЦИПЛІНА : "розподілена на"
    
    ВИКЛАДАЧ_ДИСЦИПЛІНА ||--o{ ЗАНЯТТЯ : "проводить"
    ЗАНЯТТЯ ||--o{ ОЦІНКА : "фіксує"
    СТУДЕНТ ||--o{ ОЦІНКА : "отримує"

    АКАДЕМ_ГРУПА {
        int ID_Групи PK
        string Назва
        int Рік_Вступу
    }
    СТУДЕНТ {
        int ID_Студента PK
        int ID_Групи FK
        string ПІБ
        string Email
    }
    ВИКЛАДАЧ {
        int ID_Викладача PK
        string ПІБ
        string Посада
    }
    ДИСЦИПЛІНА {
        int ID_Дисципліни PK
        string Назва
        int Кредити
    }
    ВИКЛАДАЧ_ДИСЦИПЛІНА {
        int ID_Навантаження PK
        int ID_Викладача FK
        int ID_Дисципліни FK
    }
    ЗАНЯТТЯ {
        int ID_Заняття PK
        int ID_Навантаження FK
        int ID_Групи FK
        datetime Дата_Час
    }
    ОЦІНКА {
        int ID_Оцінки PK
        int ID_Студента FK
        int ID_Заняття FK
        int Значення
    }
